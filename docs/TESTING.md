# 如何测试「上岸计划」（TESTING）

> 目的：让**非技术朋友**也能 30 秒看懂这个系统好不好用、有没有用，并给出**能改进系统的反馈**。
> 原则：先让人 30 秒看懂，再让人动手跑。三个层次配套使用。

## 层次 ①：录屏 / 演示视频（零门槛，最先做）

把工作台操作录成 3 分钟演示视频，发给任何朋友：

```
开场（10s）   ：一句话说明——"一个自动帮我汇总全网招聘信息并过滤出可投岗位的系统"
功能（90s）   ：打开工作台 → 岗位雷达卡片流 → 点岗位查看详情 → 标记投递/婉拒
亮点（60s）   ：投递状态自动回写岗位库、规则模板可自定义、每天自动推送到飞书
结尾（20s）   ：邀请对方按下面的任务卡给反馈
```

录制工具：Windows 按 `Win+G`（Xbox Game Bar）即可录屏。

## 层次 ②：网页体验（有网就行）

把发布版网页链接发给对方，直接在浏览器点开玩：
- 岗位雷达卡片流、投递追踪、简历中心、规则中心
- 让对方**自己点**，不要只看你演示

## 层次 ③：真跑代码（愿意折腾的朋友）

给对方发仓库 zip + 本文件，让对方按 [QUICKSTART.md](QUICKSTART.md) 的「第一步：跑 Demo」执行
（零配置，只需要 Python）。能跑通就说明工程上是完整可复用的。

---

## 测试任务卡（直接复制发给对方）

```
《上岸计划》测试任务卡（预计 10 分钟）

1. 打开工作台，用 1 分钟找出 3 个你觉得靠谱的岗位 → 写下你的判断依据
2. 点开任意岗位的详情 → 说说跳转是否正常、信息是否完整
3. 把某个岗位标记为「婉拒」→ 看看卡片是否从推荐列表消失、是否归入已投追踪
4. 打开「规则中心」→ 不看说明，猜猜这些规则是干什么的（能猜对几个？）
5. 最后三连问：
   a) 对找工作的人，最有用的是哪个功能？最没用的是哪个？
   b) 有用程度打分（1-5）
   c) 你会推荐给朋友吗？一句话理由
反馈直接回我微信/填飞书问卷即可，谢谢！
```

## 反馈收集建议

| 反馈渠道 | 适用 | 说明 |
|---|---|---|
| 微信直接回 | 10 人内 | 最快，适合任务卡问答 |
| 飞书问卷 / 问卷星 | 10 人以上 | 结构化打分，方便统计 |
| GitHub Issues | 开源后 | 长期沉淀 bug 与需求 |

## 拿到反馈后怎么改进（示例）

| 反馈信号 | 改进动作 |
|---|---|
| "看不懂规则中心" | 优化规则模板注释 + 加演示视频 |
| "岗位详情跳转不灵" | 修链接时效验证逻辑 |
| "推荐岗位不符合我要求" | 引导对方改自己的 rules.json（模板化的意义） |
| "没有我城市的岗位" | 补充该城市的公开渠道配置（gov/uni/corp 的 URL 列表） |
