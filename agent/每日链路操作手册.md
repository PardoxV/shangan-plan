# 上岸计划 · 每日链路操作手册

> 面向「求职Agent每日岗位推送」的**确定性运维手册**（2026-10-24 定稿）。
> 权威规则文件：`rules.json`（v5.2）；权威数据源：飞书多维表格（本地投影 `jobs.db`）；
> 全链路 = 搜索 → 过滤 → 通勤实测 → 时效验证 → 去重 → 写表 → 卡片 → UI → 评测。

---

## 1. 每日主链路（7 步）

| 步骤 | 动作 | 产物 / 命令 |
| --- | --- | --- |
| 0 | 反馈记忆读取 | `python feedback_learn.py --dump-first` → `exclusion_learned.json`（company_excluded / category_excluded / repostable 复推池） |
| 1 | 登录态自查 | 浏览器逐个打开 BOSS/智联/猎聘/51job 搜索页；空白/跳登录/验证码 = 受限，如实标注 |
| 2 | 平台搜索 | 智联/BOSS/51job/猎聘（成都），关键词：AI训练师/AI提示词/Prompt/AIGC/AI评测/AI数据运营/AI产品运营/AI内容创作/大模型标注 |
| 3 | 非平台来源（硬配额 ≥3） | 微信公众号（成都人才招聘网/青聚锦官城/四川人才）、院校就业网、高校官网、成都人事考试网/成都人才网/人社局/国资委/区县管委会、AI 公司官网 careers 成都岗、通用搜索兜底、专精特新名单、IT桔子/36氪 B轮+成都 AI 企业 |
| 4 | 硬规则过滤 | 规则以 `rules.json` v5.2 为准：薪资到手≥5000（税前4K以下/15K以上不推）、通勤骑行30/公交40-60/地铁50分、周末至少休一天、排除客服/主播/销售/服务员/外卖/送货/网销/工单/纯体力/外呼/强销售/常出差；skill_gate（剪辑/设计/代码/CET-4-6/1-2年经验无豁免不推）；外包黑名单 46 家 + 景烁公司级拉黑 |
| 5 | 逐链接时效验证 | 浏览器打开详情页；命中"已关闭/已下线/职位不存在/404"=关闭剔除；文本>80字=有效。**已关闭岗绝不推** |
| 6 | 增量去重 | 对比 `<PROJECT_ROOT>\jobs_data\pushed_jobs.json`（title+company 双键）+ 多维表格投递状态；未投好岗可复推（重新验证，单日≤5） |
| 7 | 写表+卡片+UI+评测 | 见第 2-4 节 |

## 2. 确定性推送链路（可复跑）

脚本均在 `job-agent\` 目录运行。

```bash
# ① 反馈学习（第〇步）
python feedback_learn.py --dump-first [--min-score 70]
#    → exclusion_learned.json（company_excluded 公司级拉黑 / category_excluded 类别累计婉拒≥2 排除 / repostable 复推池）

# ② 推送编排（核心引擎 engine() 已抽成纯函数，可注入测试）
python push_pipeline.py --date YYYYMMDD [--candidates <file>] [--repost-limit 5] [--write] [--verify]
#    → to_push_<date>.json / records_create_<date>.json / daily_<date>.json
#    注意：候选未附时效验证+通勤实测时 pushed=0（pending_verify 如实上报，不虚报配额）；
#    --write 才会真正写多维表格；--verify 跳过时效验证假定在招（仅测试用）

# ③ 补推检查（每日定时任务入口）
python check_daily.py [--date YYYYMMDD] [--dir <job-agent 目录>]
#    exit 0 = DONE（当日已推送）；exit 2 = NOT_DONE（需补跑全流程）
```

**⚠️ 防覆盖红线（2026-10-23 事故教训）**：
- `daily_<date>.json` 是**当日真实推送证据**，禁止用 dry 验证覆盖。
- 跑 `push_pipeline.py --date <历史日期>` 前，先确认该日已无真实 daily，或先备份：`copy daily_<date>.json _backup\daily_<date>.json.bak`。
- 恢复被覆盖的 daily：`python restore_daily_20261023.py`（从多维表格真实记录重建，20261023 专用；其他日期按同样思路手工重建）。

## 3. 写表与卡片（参数固定）

```bash
# 写多维表格（base_token 固定）
lark-cli base +record-batch-create --base-token YOUR_BASE_TOKEN \
  --table-id YOUR_TABLE_ID --json @records_create_<date>.json --as user
#    JSON 扁平结构 {"create_records":[{字段:值,...}]}；新记录投递状态="未投"
#    select 合法值：来源=智联/BOSS/51job/猎聘/高校就业/政府官网；作息=双休/未注明/实习；状态=推荐/优先/自查/待核/已投

# 发飞书卡片（Card 2.0，用户 open_id 固定）
lark-cli im +messages-send --user-id YOUR_OPEN_ID \
  --msg-type interactive --content @card_<date>.json --as user
#    完整清单链接：https://my.feishu.cn/base/YOUR_BASE_TOKEN
```

## 4. UI 重建与评测（写表发卡后必须执行）

```bash

# ⑤ 评测回流

```

## 7. 常见故障速查

| 现象 | 处理 |
| --- | --- |
| BOSS 403 反爬/登录失效 | 如实标注受限，转 51job/智联/猎聘 + 非平台渠道补配额 |
| 51job 桌面页滑块 | 换移动版或标注无法验证，不计入 |
| 高德骑行接口无返回 | 用公交实测替代并注明（20261023 曾发生） |
| 薪资字段"面议" | 写表前电话/邮件确认到手≥5000，未确认标"待核" |
| daily 被 dry 覆盖 | 见第 2 节红线；用 restore 脚本或手工从表内记录重建 |
| 非平台配额不足 | 如实上报缺口，不凑数（历史多次发生） |
| all_records_raw 读一半/记录时有时无 | dump_all.py 已原子写（tmp+os.replace），不会半截；仍报错则重跑 dump_all（损坏提示见 sync_snapshot） |

## 8. 工作台投递状态/反馈闭环（v20261024）

本地工作台 http://localhost:8123（`job-workbench\启动工作台.bat`）：

- **投递追踪视图**：已投递岗位每行两个下拉——状态（已投/已回复/面试/婉拒/入职）+ 反馈（待定/合适/不合适/已投），变更即 `POST /api/status` 写回多维表格（写后回读验证），无需再在豆包对话里改。
- **数据链**：多维表格「投递反馈」→ `dump_all.py` → `sync_snapshot.py`（已含 fb 字段）→ `jobs_build.py`（JOBS 内嵌 `fb`）→ 工作台下拉。改 UI 数据后必须重跑 `python build_workbench.py`。
- **反馈学习联动**：投递反馈=婉拒 的记录会被 `feedback_learn.py` 学习进 `exclusion_learned.json`（公司级拉黑/类别累计婉拒≥2 排除/复推池），下一次推送自动生效。
- **接口契约**：`/api/status` body `{record_id, state, feedback?}`；无 token 401；非法 state/feedback 400（白名单 APPLY_STATES/FEEDBACK_STATES）；已投自动补投递日期。
- 改动后重启服务：停掉旧 python server.py 进程 → `Start-Process python server.py`。
